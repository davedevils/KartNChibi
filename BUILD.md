# KnC - Build Guide

## Build Structure

```
KartNChibi/
├── build/              # KnC.sln, generated by cmake --preset vs2022
├── build-ninja/        # Ninja configure, any platform other than the VS solution
├── build-server/       # Servers, their own CMake project
├── build-bgfx-tools/   # bgfx shader compiler, built once by build_shaderc.ps1
├── build-headless/     # Headless client
├── build-clientpatch/  # Client patch DLL
├── build-kartclient/   # Client physics port, its own CMake project
├── release/            # All executables and DLLs land here
├── logs/               # Build logs written by the scripts
└── Data/               # Runtime assets
```

Every `build*/` tree is intermediate and ignored by git, never commit one.

---

## Quick Start

### First-Time Setup
```
git submodule update --init --recursive
powershell -File scripts/build/build_shaderc.ps1
```
The submodules are bgfx, bimg and bx under `thirdparty/bgfx`. `build_shaderc.ps1` builds the bgfx shader compiler once into `build-bgfx-tools/`, the render module needs it at configure time to compile its shaders. Skip it and the configure warns and drops `KnCRender` and `model_viewer`, everything else still builds.

### Build (Engine, Tools, Tests)
```
cmake --preset vs2022
cmake --build --preset vs2022
```
Writes `build/KnC.sln`. Executables land in `release/`.

### Build with the Scripts
```batch
powershell -NoProfile -File scripts\build\build_sln.ps1
```
Same result through MSBuild, log in `logs/msbuild_sln_console.log`.

- `build_sln.ps1` whole solution, log `logs/msbuild_sln_console.log`
- `run_msbuild.ps1` engine only, log `logs/msbuild_console.log`
- `build_engine_and_tools.ps1` engine and the viewers
- `build_shaderc.ps1` the bgfx shader compiler, once

All four find MSBuild with vswhere, Visual Studio 2022 first, and never use a hard coded path.

### Any Other Platform
```
cmake --preset ninja
cmake --build --preset ninja
```
Configures into `build-ninja/`.

## Output Files

After compilation, executables land in `release/`.

| Executable | Description |
|------------|-------------|
| `model_viewer.exe` | New bgfx renderer, opens one NIF in a window |
| `map_viewer.exe` | Map viewer |
| `ui_editor.exe` | UI editor |
| `dat_manager.exe` | PAK manager |
| `nif_smoke.exe` | Walks a NIF tree, reports every block it could not decode |
| `nif_rewrite.exe` | Reads and writes every NIF, diffs the bytes |
| `test_*.exe` | Engine and RHI unit and integration tests, one executable per suite |

## Servers

The servers are their own CMake project.

```
cmake -S server -B build-server -G "Visual Studio 17 2022" -A x64
cmake --build build-server --config Release
```

Binaries in `build-server/bin/Release/`. The Windows build links `thirdparty/mariadb-connector-c`.

Server unit tests are off by default, `-DKNC_BUILD_TESTS=ON` on the server configure, gtest is fetched over the network at configure time.

### Docker Image

The one the release package ships:

```
docker build -f server/Dockerfile -t knc-server:dev .
docker save knc-server:dev -o <package>/server/knc-server-image.tar
```

Run it with `server/docker-compose.yml`, settings in `server/.env`.

## Other Projects

Small standalone CMake projects, each with its own tree, also reachable from the root solution.

```
cmake -S tools/headless -B build-headless -G "Visual Studio 17 2022" -A x64
cmake --build build-headless --config Release

cmake -S tools/clientpatch -B build-clientpatch -G "Visual Studio 17 2022" -A Win32
cmake --build build-clientpatch --config Release
```

`tools/headless` is the headless client, `tools/clientpatch` is the client patch DLL, x86 only.

The client physics port, a 1 to 1 port of the stock client kart physics, no engine dependency. It builds `KnCKartClient`, 9 test executables under `tests/`, and `ghost_dump`/`ghost_compare` from `tools/replay`:

```
cmake -S games/kart/physics/client -B build-kartclient -G "Visual Studio 17 2022" -A x64
cmake --build build-kartclient --config Release
```

## Build Options

```cmake
option(KNC_BUILD_RENDER "Build the bgfx render module and its tools" ON)
```

`-DKNC_BUILD_RENDER=OFF` leaves bgfx, the new renderer and its tools out of the build entirely. `-DKNC_BUILD_TESTS=ON` on the server configure turns on the gtest suite.

## Cleanup

To clean completely:

```
rmdir /s /q build build-ninja build-server build-bgfx-tools build-headless build-clientpatch build-kartclient
rmdir /s /q logs
```

`release/` holds real output next to it and is not removed by this, delete it by hand if needed.

## Prerequisites

- Windows 10 or 11, x64
- Visual Studio 2022, any edition, with the C++ desktop workload, toolset v143
- CMake 3.21 or later
- Docker Desktop for the server image
- Python 3 for the audit scripts under `tools/`

## Common Issues

### "openssl/err.h not found"
Pre-existing, the web-admin project only, ignore it.

### Launcher WebView2 package restore
`launcher/packages/` is git ignored, nothing under it is committed. On
configure, `launcher/CMakeLists.txt` downloads the WebView2 NuGet package
straight from nuget.org into `launcher/packages/Microsoft.Web.WebView2.<version>/`
and extracts it with CMake's own `file(ARCHIVE_EXTRACT)`, the same self fetch
pattern it already uses for `webview.h`. This needs network access on first
configure only, later runs reuse the extracted `build/native/include/WebView2.h`
and skip the download. No manual NuGet restore step is needed. Set
`-DBUILD_LAUNCHER=OFF` to skip the launcher target entirely, offline or
otherwise.

### Configure warns and skips KnCRender / model_viewer
`build_shaderc.ps1` was not run, or the submodules were not initialized. Run `git submodule update --init --recursive` then `build_shaderc.ps1`.

### "vswhere not found"
Install Visual Studio 2022 or later, vswhere ships with the installer.

### Solution will not regenerate
Do not point an older generator at `build/`, Visual Studio 2017 support is gone. Delete `build/` and reconfigure with `cmake --preset vs2022`.

## Project Structure

```
KartNChibi/
├── server/             # Login server, game server, web admin, SQL scripts, Docker image
├── shared/             # Code shared by the servers, packets, sessions, database, logging
├── engine/             # C++ engine, only render and formats, the bgfx stack
├── games/kart/         # physics/client, the 1 to 1 port of the stock kart physics
├── client/             # The client rewrite, builds as knc_client, guarded on KnCRender and glfw
├── tools/              # Headless client, spy dll, MITM proxy, viewers, NIF checks
├── tests/              # Engine and server tests
├── docs/               # Protocol, systems, engine and tool documentation
├── thirdparty/         # External dependencies, bgfx, bimg, bx, mariadb-connector-c
├── scripts/            # Build and utility scripts
├── Data/               # Runtime assets
└── CMakeLists.txt      # Root CMake configuration
```

## Development Workflow

1. Modify code in `engine/`, `games/kart/`, `server/`, `tools/`, etc.
2. Rebuild with `cmake --build --preset vs2022` or one of the scripts
3. Test the executable in `release/`
4. Repeat

## Notes

- Every build tree is `build*/` and ignored, never commit one
- Logs go to `logs/`, never the root
- Do not regenerate `build/` with a generator older than Visual Studio 2022
- The old `scripts\build.bat` and `Debug/` folder are gone, everything is `Release` config through the presets and scripts above
