## C2S PopupClose

```
+0x00  u32  popup_context   the +0x66AC slot of popup object 0xEAB878, reset to -1 by sub_454FE0
size   4
```

The only sender is sub_454E40, the Enter and left button path of popup kind 0x1F (object
0xEAB878, key handler sub_455040, mouse handler sub_455070 from the popup manager switch
sub_453A80 and sub_454350). That popup has draw, update, key, mouse and destroy entries in the
manager but NO open path anywhere in the image: nothing writes its text lines, its +0x08
visible byte or its +0x66AC value. The MISSION_ENTER confirm popup sub_4556D0 is a different
object (0xEB1F40, kind 0x2E) and its OK button sends C2S 0x0090.
So this frame cannot be produced by the shipped client, and if it were the dword would be the
reset value. The server parses it and ignores it. No S2C case 141 so no reply is possible.
