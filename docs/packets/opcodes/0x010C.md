## Our server

`RoomCraftPackets::objectDefinition` builds one frame per row of `room_object_def`
with its `room_object_price` slots. `RoomCraftHandler::pushObjectCatalog` sends the
whole catalog at login and tops it up on stage open, deduped per session. A def
with no price row still ships one inert zero row so the tile draw never derefs.

The recording carries 71 rows, keys 8000 to 8070, by category 11 Sky, 13 Floor, 4 BgObj,
32 Object, 11 Effect. Ours shipped 65 until migration 061 added the four floors
`Ani_Floor03` `dollhouse01` `fence01` `floor05` and the two back objects `_mountain01`
`_waterfall01`, all six shipped in the pak. The recording names those six by their folder
because `Define/<lang>/def_trans_index.txt` has no title key for them, so our rows do the
same. The shop tile wants a price, `shop_roomcraft_grid_draw` 0x41A160 keeps a row only
when `enabled_flag` is not zero, when the category matches the open sub tab, and when the
first price option resolves in the 0x00C6 table, so the six new rows carry the usual
2006 3006 1006 triple. The recording enables only 10 of its 71 rows, ours sell all of
them, that is the emulator rule of migration 050.
