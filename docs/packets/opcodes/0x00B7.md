## S2C BuyOk

```
+0x00  u32  category   0..6, above 6 reads NOTHING further but still pops MSG_SUCC_BUY
+0x04  u32  gold       -> 0x01A20B14
+0x08  u32  astro      -> 0x01A20B10
+0x0C  record by category
size   12, or 12 plus the record
```

```
0 -> blob[0x2C]  -> 0x844720 cap 64
1 -> blob[0x38]  -> 0x845228 cap 64
2 -> blob[0x1C]  -> 0x847C38 cap 64
3 -> blob[0x1C]  -> 0x846030 cap 256
4 -> blob[0x1C]  -> 0x857258 cap 64
5 -> blob[0x30]  -> 0x863D68 cap 256
6 -> u8 hasExtra FIRST, then blob[0x84] -> 0x878E84, then blob[0x34] when hasExtra == 1
```

CATEGORY 6 TAIL ORDER IS u8 FIRST HERE and blob FIRST in 0x00ED and 0x0135.
Do not share one serializer.
MONEY ORDER is (gold, astro), REVERSED versus 0x0098.
Every category erases by BASE KEY rec+0x04 before appending, except category 5 with
rec+0x08 == 3 which appends blind.
There is NO failure variant, refuse a purchase with a message box packet.

## C2S Buy

```
+0x00  u32           category
+0x04  u32           base_key
+0x08  i32           price_key   -1 when the client could not resolve it
+0x0C  UTF16LE wstr  recipient_or_account_name
size   12+2*(n+1)
```

Category enum cross proved: 0 character, 1 kart, 2 consumable, 3 equipment part, 4 pet,
5 room craft, 6 car craft. Uses the 1000 ms send path with MSG_WAIT up.

## Our server

`ShopHandler::handleBuy` gates on `ShopPackets::validatePurchase`, which reads the price row,
then `shop_option`, then `shop_definition`, then the level, the pet condition and the wallet.
A missing definition row answers `UnknownDefinition`, and `resultMessageKey` has no locale key
for it, so the client shows MSG_UNKNOWN_ERROR. That was the whole driver accessory refusal,
fixed by seeding category 3 in migration 062, see [0x00C2](0x00C2.md).

A category 1 buy of a factory chassis (2026-09-24): the kart record of this ack already carries period
mode 3 and 500 durability, then `CarCraftHandler::pushFactoryLoadout` sends the seven 0x0109 rows of its
BASIC set and the full 0x0107 with one built row per chassis, since the category 1 reader only appends
the kart and the garage lists a chassis only through a built 0x0107 row, see [0x0107](0x0107.md).

### The currency, 2026-09-23

The client never names a currency, it prints the sale with the Astro icon and the base with the Gold icon
(0x45E36B, `UI_Shop_iteminfo_buy_Cash` at `this+0x138`, `UI_Shop_iteminfo_buy_Peri` at `this+0xA0`).
`ShopPackets::loadPrice` now takes the currency from the sale (`ShopPackets::currencyOf`), a sale row is
charged in Astro and answered with MSG_NO_CASH when short, a base row in gold. The `currency` column is not
read any more. Before, a sale row was billed in gold while the client printed Astro. A buy of the Gacha Coin
2000 or the Gold Coin 2001 lands a mode 2 row with one more coin whatever unit its row prints, see
[0x00ED](0x00ED.md). The price rows and tiers are in [../SHOP_CATALOGUE.md](../SHOP_CATALOGUE.md), they need
the new image and migration 068.
