# 0x0019

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | ServerRedirect | sub_479340 | CharCreatePackets::serverRedirect | strlen+9 | redirect | PROVEN |
| C2S | ReconnectRequest | sub_4817E0 | GameServer::handleServerQuery | strlen+9 | redirect | PROVEN |

## C2S ReconnectRequest

```
+0x00  ASCII cstr  host   the Network2.ini host
 var   u32         port   the Network2.ini port
 var   u32         mode   hardcoded literal 4 at all four call sites
size   strlen(host)+9
```

The client hands back its own configured gateway and asks to be sent there.
mode 4 is exactly the case where the client IGNORES the port in the S2C reply.

## S2C ServerRedirect

```
+0x00  ASCII cstr  host   dest char[128] then strcpy into a 255 byte buffer
 var   u32         port
 var   u32         mode
size   strlen(host)+9
```

ASCII, NOT UTF16, and it is the FIRST field. Executed one frame later: disconnect then
connect. ASYMMETRY: when mode == 4 the client IGNORES the packet port and uses the
Network2.ini port, default 50017. Any other mode uses the packet port.
On failure it retries 127.0.0.1:0 when mode == 11, else the ini host, then shows
MSG_SERVER_NOT_READY type 1 or MSG_CONNECT_FAIL type 2. After connecting it sleeps 1000 ms
then sends C2S 0x00A7 with `mode` forwarded verbatim as target_stage.

## Our server

`GameServer::handleServerQuery` in `server/game/src/GameServerRoomHandlers.cpp` used to answer
a bare ack, so the stock client never left the game socket. It now reads the host, the port and
the mode the client sent and answers the real S2C 0x0019 with our own login host, the login
port and the mode echoed back. The host comes from `LoginServer.public_host` in the ini, else
the environment variable `KNC_LOGIN_PUBLIC_HOST`, else `LoginServer.host`, because the docker
service name the game server dials is not a host the client can reach.

The client then disconnects, connects to the login port, sleeps 1000 ms and sends a bare
C2S 0x00A7 stage 4 with no 0x00FA in front. See [0x00A7](0x00A7.md) for the login side.
