## S2C owned append, ONE record, NO count (family 0x009D 0x009E 0x009F)

```
0x009D  blob[0x2C]  owned character  -> 0x01A56BD0, cap 64
0x009E  blob[0x38]  owned kart       -> 0x01A576D8, cap 64
0x009F  blob[0x1C]  owned part       -> 0x01A584E0, cap 256
```

Record layouts are identical to the 0x001B, 0x001C and 0x001E rows.
No dedupe. Overflow raises the TYPE 2 dialog which CLOSES THE SOCKET.
0x009F appends WITHOUT the remove by key step that 0x001E does.
