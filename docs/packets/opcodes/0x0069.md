# 0x0069

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | CarEffectBroadcast | sub_47AF00 | *ItemPackets::effectApply | 7 | items | PROVEN |
| C2S | HitReport | sub_481B60 | *ItemPackets::parseHit | 3 | items | PROVEN |

## S2C CarEffectBroadcast

```
+0x00  u32  player_id
+0x04  i16  effect_code
+0x06  u8   flag   read and discarded
size   7
```

DANGER: the i16 and the u8 are read INSIDE the lookup guard, an unknown id drops 3 bytes.
Codes with a case: 100 200 300 crash and spin, 700 bee swarm, 1000 ice.
ALL OTHER CODES INCLUDING 1100 ARE DROPPED, flash is victim local only.

## C2S HitReport

```
+0x00  i16  effect_code   only the low 16 bits of the int argument go on the wire
+0x02  u8   flag          every call site passes literal 1
size   3
```

THE VICTIM SENDS IT, not the shooter and not the server. Observed wire codes 100, 300,
700 hive, 1000 ice, 1100 flash. Codes 200 400 500 600 800 900 are set locally but never
transmitted. Note the size asymmetry with S2C 0x69.

## Our server

`RaceHandler::handleHitReport` in `server/game/src/handlers/RaceHandler.cpp`, routed from
case 0x69 in `server/game/src/GameServerDispatch.cpp`:

1. drop unless the room is Racing
2. drop the code unless `ItemPackets::hitShouldRebroadcast` says yes, see the gate below
3. drop when the victim is not on the race roster, the receiver reads the i16 and the u8
   INSIDE the id guard so an unknown id eats 3 bytes
4. `ItemPackets::ItemModel::applyEffect` records the effect and its expiry
5. `room->broadcast`, the sender INCLUDED. The stock sender `FUN_00481B60` skips the local
   apply, so the victim needs its own echo to see the effect

THE GATE is two lists in `server/game/src/packets/gen/ItemPackets.cpp`:

```
effectActionable       100 spin, 200 bump, 300 crash, 700 hive, 1000 ice
effectReportedByClient 100 spin, 300 crash, 700 hive, 1000 ice, 1100 flash
hitShouldRebroadcast   both,  so 100, 300, 700 and 1000 only
```

200 bump is actionable but nothing ever sends it. 1100 flash is sent but is victim local, the
receiver has no case for it. Both are dropped.

THE EFFECT CODES our model knows, `effectVelocityMultiplier` in the same file, the number is
the velocity the victim keeps:

```
   0 none            1.000     500 turtle zone     0.934
 100 spin            0.968     600 rabbit latch    1.000
 200 bump            0.980     700 hive            0.940
 300 crash           0.000     800 heavy stun      1.000
 400 thunder area    0.880     900 bluerabbit      1.000
                              1000 ice             0.880
                              1100 flash           1.000
```

`effectDurationMs` gives a fixed end to 100 spin only, every other code returns 0 and dies on
a client side test, so our tick never expires it.

WHERE A CODE COMES FROM when the victim is a CPU car, since a bot sends nothing.
`RaceHandler::tickBots` broadcasts the same S2C 0x69 itself in two cases. A hazard under the
bot, mapped by `hazardEffect`, spike and dung give 100, bomb gives 300, ice gives 1000, hive
gives 700. And a queued hit from `RaceHandler::queueBotHit`, a rocket lands 300 crash after
1500 ms and a turtle lands 100 spin after 2500 ms. A bot already stunned is skipped.

`server/game/src/handlers/ItemHandler.cpp` used to hold a second implementation of this
handler that nothing routed to. It is gone, the file keeps only the two wired handlers,
`handleAbilityClass` for 0xF2 and `handleAbilityFire` for 0xCD.
