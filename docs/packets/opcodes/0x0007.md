# 0x0007

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | LoginAccept | sub_479020 | CharCreatePackets::loginAccept | 1228 | auth | PROVEN |
| C2S | LoginRequest | sub_480430 | GameServer::handleClientAuth | 8+2 strings | auth | PROVEN |

## C2S LoginRequest

```
+0x00  ASCII cstr    client_version   literal "178", 4 bytes
+0x04  u32           target_stage     4 at both first login call sites
 var   UTF16LE wstr  account_id
 var   UTF16LE wstr  password_or_launcher_token
size   8+2 strings
```

MIXED ENCODING, ASCII first then two UTF16. Queued with a 1000 ms delay.
Byte `0x01ADF270` picks 0x0007 vs 0x00A7. Zeroed once at process start, set to 1 by BOTH
the S2C 0x0007 and S2C 0x00A7 handlers, never reset. So the FIRST auth of a process is
always 0x0007 and every auth after a redirect is 0x00A7.

## S2C LoginAccept

```

+0x004 blob[0x4C8] profile          one raw qmemcpy, internal padding IS on the wire
```

Side effects: `FindWindowA("TOGPLauncherFrame")` then `SendMessageA(hwnd, 0x4C8, 0x2710, 30)`,

Reset path writes -1 into the two selection ids, so -1 is the no selection sentinel.
NOTE the two agents disagree on the sub offsets, see CONFLICTS C1.

## Our server, the gold and exp conflict is LIVE in our own code

Our login server and our game server do not agree on the same three dwords, and only the
game server follows this page.

`HandshakeHandler::sendSessionInfo` in `server/login/src/handlers/HandshakeHandler.cpp`
writes the blob it puts behind the player id like this:

```
+0x000 u32       account id
+0x004 UTF16     session token, up to 32 chars in place
+0x486 wchar[12] nickname
+0x4A4 i32       GOLD        <- this page says exp_current
+0x4A8 i32       0           astro, hardcoded zero
+0x4AC i32       CASH        <- this page says gold
+0x4B0 i32       selected character instance id, -1 when none
+0x4B4 i32       selected kart instance id, -1 when none
```

It writes nothing else. The band at +0x4A0, the level at +0x4A1 and the whole tail from
+0x4BC to +0x4C7 go out as zero, so a stock client logging in through our login server shows
level 0 and an empty exp bar, and it reads our gold as exp and our cash as gold.

`CharCreatePackets::profileBlob` in `server/game/src/packets/gen/CharCreatePackets.cpp`,
which builds both the game server 0x0007 and the 0x00A7, follows this page instead. Note its
literal offsets run 4 higher because that function writes the player id at its own +0x000,
so its `+0x4A8 expCurrent` is blob +0x4A4 and its `+0x4B0 gold` is blob +0x4AC.
The older `PacketBuilder::writePlayerInfo` in `server/game/src/packets/PacketBuilder.cpp`
also follows this page, exp at +0x4A4 and gold at +0x4AC.

The login server is the odd one out. See CONFLICTS C1 in `../PACKET_REGISTRY.md`.
