# 0x00B8

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | DeleteOk | sub_484690 | *InventoryPackets::deleteAck | 8 | shop | PROVEN |
| C2S | SellDelete | sub_4844A0 | *InventoryPackets::parseDelete | 8 | shop | PROVEN |

## S2C DeleteOk

```
+0x00  u32  category   0..5, above 5 is a no op
+0x04  u32  key
size   8 exactly, no record, no trailing fields
```

KEY SPACE TRAP: field +0x04 is the definition BASE KEY for categories 0 1 2 3, but the
INSTANCE UID for category 5. Category 4 and category 6 remove nothing locally.

## C2S SellDelete

```
+0x00  u32  category
+0x04  u32  key   base key for 0..4 and 6, instance uid for 5
size   8
```

MSG_WAIT is up, answer or the client hangs. Only sent when the row active flag is zero.

The client clears the active flag on its own clock: `sub_451C90` zeroes the period block +0x0C
(the row +0x18) once a day row passes today (`sub_451C30`, 365 times tm_year plus tm_yday minus 365)
or a count row reaches 0, then the garage draws Expired and offers Delete and Buy.

## Our server

`InventoryHandler::handleDelete`. It used to refuse with MSG_UNKNOWN_ERROR whenever the stored
`active_flag` was still 1, and nothing on the server ever clears it, so the Delete of an expired
row always failed: the black paint of HlTestTwo, day 45886 on 2026-09-23 (day 45890), is that case.
Now the row counts as expired when the stored flag is 0 or `ownedRowExpired` of
`server/game/include/util/GarageSlotRules.h` says the day or count ran out, the same rule as
`sub_451C90`. A deleted part that a kart still wears goes back to the kart def key (9007 paint,
9100 plate, 0 antenna) on every owned kart, and 0x00BC follows the ack so the stand drops it, since
`sub_484690` only removes the owned row. A row still running answers MSG_UNKNOWN_ERROR as before.
