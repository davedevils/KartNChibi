## S2C SystemChatLine

```
+0x00  u32           unused        no reader, send 0
+0x04  UTF16LE wstr  name          dest slot 28 bytes, CAP 13 wchars incl NUL
 var   ASCII cstr    message_key   dest char[260], CAP 259
 var   u32           type          MUST be 5 or the handler draws nothing
size   4+2*(n+1)+strlen(key)+1+4
```

THE MIXED ENCODING PACKET, name is UTF16 and message_key is ASCII.
message_key is a localisation key, NOT display text, an unknown key falls back to the raw
key rather than crashing.
Destination by stage: 8 lobby, 9 room, 11 race, any other stage drops it.
Both caps are stack smashes, not truncation.
The handler formats the resolved key alone with `%s` (`FUN_0047EC00`), the name is read and never
shown, then appends the line as type 5 to the lobby or room chat (`FUN_004088C0`) or the race chat
(`FUN_004016E0`).

## Our server

`SocialHandler` sends it through `sendSystemKey` for the refusals of the messenger verbs: whisper,
small talk, room invite and the invite answers, see [0x006C](0x006C.md). Since 2026-09-23 a room
invite sent from the lobby gets `MSG_UNSUPPORT` here instead of nothing.
