# 0x0023

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | RoomListRowFieldUpdate | sub_479BE0 | PacketBuilder::lobbyRoomState | 8 | lobby list | PROVEN |

## S2C RoomListRowFieldUpdate

```
+0x00  u32  room_id
+0x04  u32  playing_flag   -> record+0x74, 0 waiting art, nonzero Lobby_Room_Play art and the grey mode icon
size   8
```

sub_407660 writes ONE dword at room list record+0x74. Not found is a silent no op.
The row draw sub_407B50 tests it at 0x407BB8.
No C2S 0x23 exists, the real ready toggle is C2S 0x33.

## Our server

Inside a room this opcode carries a member row, not a lobby row. `PacketBuilder::playerUpdate`
in `server/game/src/packets/PacketBuilder.cpp` builds it:

```
+0x00  i32  player_id   the character id of the member
+0x04  i32  packed      slot | team << 8 | ready << 16, one byte per field
size   8
```

Two senders. `GameServer::handlePlayerReady` in `server/game/src/GameServerRaceHandlers.cpp`
broadcasts it on every ready toggle with the live slot, team and ready of that member.
`GameServer::leaveCurrentRoom` and `GameServer::handleLeaveRoom` in
`server/game/src/GameServerRoomHandlers.cpp` broadcast it for the NEW host after the old
host left, and those two fill only `id` and `slot`, so team and ready go out as 0.

`shared/src/include/net/Protocol.h` gives 0x23 two names for this reason,
`S_PLAYER_UPDATE` and `S_LOBBY_ROOM_STATE`. Both are 8 bytes, so the receiver tells them
apart by its own stage.
Our dispatch also routes an incoming 0x23 of one byte to the ready toggle,
`CMD::C_PLAYER_READY`, next to the C2S 0x33 the stock client really sends.
