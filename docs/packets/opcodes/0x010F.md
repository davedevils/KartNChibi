# 0x010F

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | RoomCraftSaveAck | sub_47DA00 | *RoomCraftPackets::saveAck | 4+0x30*n | roomcraft | PROVEN |
| C2S | RoomCraftSaveReq | sub_483450 | *RoomCraftHandler::handleSave | 4+0x30*n | roomcraft | PROVEN |

## C2S RoomCraftSaveReq

```
+0x00  i32  count
 then  count x blob[0x30] dirty record, identical layout to 0x010D
size   4+0x30*count, count <= 170 by the frame cap
```

Only records whose position, yaw or placed flag differ from the master copy are sent.
If nothing changed the client shows MSG_SAVE_DONE locally and sends NOTHING.

## S2C RoomCraftSaveAck

```
+0x00  i32  count
 then  count x blob[0x30] record
size   4+0x30*count
```

Only +0x00 as the lookup key and +0x0C..+0x1F position, yaw and placed flag are used.
+0x04..+0x0B and +0x20..+0x2F are read and discarded but MUST be present.
CRASH CONFIRMED AT INSTRUCTION LEVEL: the lookup returns 0 on a miss and the handler does
`LEA ECX,[EAX+0xC]` and stores with NO `TEST EAX,EAX` in between. An instance_id the client
does not hold writes to VA 0x0000000C.
Only echo ids the client already holds. count 0 is always safe and still closes the dialog.

## Our server

C2S 0x010F routes early as `C_ROOMCRAFT_SAVE` to `RoomCraftHandler::handleSave`
through `RoomCraftPackets::parseSaveRequest`. It echoes only instance ids the client
already holds, so the sub_47DA00 lookup never stores through a null. It merges the
position, the yaw and the placed flag into `player_item_instance`, keeps the object
key category and period server owned, checks the placement caps, and answers 0x010F.
Every early out still answers with the empty ack so MSG_WAIT closes.
