## C2S RaceProgressScore

```
+0x00  u32  progress_score
size   4
```

C2S ONLY, there is NO dispatcher case 103.
`score = frac*bucket + (next_cp-2 wrapped)*bucket + lap*5000` with `bucket = 5000/n_cp`,
so `score / 5000` equals completed laps. Gated to one send per 300 ms unless the value
changed. In the 20000000 rally world it instead sends distance to the next waypoint plus
10000*waypoint on a 1000 ms gate. Stops once 0x3C sets car+2521.

## Segment fraction

The score is not a raw distance, the fractional part is a projection on the COL head
points. `SpawnPackets::loadColCheckpoints` in `server/game/src/packets/gen/SpawnPackets.cpp`
reads the first header dword as the checkpoint count and the next `count` 12 byte triples
as the checkpoint points, one per checkpoint, index 0 being the `START` face. The client
reads the same head, `readColHead` in `client/race/TrackData.cpp` fills
`checkpointPoints` from bytes 16 onward with the same stride.

`RaceScreen::progressScore` in `client/screens/RaceScreen.cpp` then builds the value:

```
bucket  = 5000 / checkpoint_count
a       = point[current_checkpoint]
b       = point[(current_checkpoint + 1) % count]
frac    = clamp01( dot(pos - a, b - a) / |b - a|^2 )    XY only, Z ignored
wrapped = (next - 2) mod count
score   = frac*bucket + wrapped*bucket + laps*5000
```

A track with no readable COL head falls back to `laps * 5000` with no fraction at all.

## Our server

`RaceHandler::handleProgress` in `server/game/src/handlers/RaceHandler.cpp`, routed from
case 0x67 in `server/game/src/GameServerDispatch.cpp`, stores the score on the roster row
and nothing else. `calculatePositions` ranks finished racers by time first and everyone
else by the server place key of `docs/systems/RACE_COMBAT.md`, then by this score, then by
lap, then by z. This score alone misranks a car between START and checkpoint 1. The rank it produces is what the S2C 0x45
standings carry, and the leading human score is what the CPU cars rubber band against in
`tickBots`. It never advances
a lap, the lap comes from 0x41 only. A client lap count more than one ahead of the server
lap count logs a warning once per racer.

## The server driven CPU cars

`BotDriver::progressScore` in `server/game/src/handlers/RaceBots.cpp` must speak this exact
space, `laps * 5000` plus the lap bucket, because `RaceHandler::calculatePositions` sorts the
humans and the CPU cars through one comparator and `tickBots` measures its rubber band against
the best human score. The bot used to add one whole lap, so every CPU car ranked a lap ahead of
every human on the 0x45 standings and the rubber band read a permanent lead and held the whole
field at 0.88 pace. `tests/server/test_room_bots.cpp` checks `score / 5000` equals the completed
laps.
