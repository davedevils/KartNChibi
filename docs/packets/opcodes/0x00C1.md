## S2C ItemDefinition

Handler `item_catalog_recv_0xc1` 0x47F6B0, store `item_catalog_store` 0x450750 into the container
0x01A27640, cap 64, stride 0xC4, count at container+0x3104. Lookups `item_catalog_lookup` 0x4508C0 by
key at rec+0x08, `item_catalog_by_index` 0x450790, `item_catalog_count` 0x450820.

```

+0x00  +0x00   visible_flag        u32        shop_tile_draw_items 0x419CC0 skips zero, item_catalog_by_index flag mode
+0x04  +0x04   badge               u32        shop_tile_draw_items, 1 or 2 draws one of the two tile overlays new and hot
+0x08  +0x08   item_def_key        u32        LOOKUP KEY item_catalog_lookup 0x4508C0

+0x14  +0x14   icon_name           cstr 33    item_icons_load 0x4424F0 "Parts/item_%s_%02d.png" frames 1 and 2
```

No stat block. Item base key 1000 is the race consumable driven by C2S 0x00CB, 2000 is the gacha
ticket. Migration 060 adds the repair scrolls 3000 (use type 4, icon `repair_half`, price row 4101
unit type 3 amount 250) and 3001 (use type 5, icon `repair_full`, price row 4102 amount 500), the
client ships both icons in `Image/Parts`, the real burst has no such row, its two 0x00C1 rows are
the gacha coins 2000 and 2001 with use type 0. The repair rule is in [0x00C0](0x00C0.md). Before 2026-09-15 our server wrote the display name key into the first string and the icon
name into the second, the client reads them the other way round, PartStatPackets::itemDef now sends
icon_key first and display_name_key second.

### Our server after the audit of 2026-09-23

The two burst rows sell on the burst options: 2000 on 4001 (1000 Astro permanent) and 2001 on 4002 (2500 gold
permanent), one option each, and a buy adds one coin to a mode 2 row the gacha box spends, see [0x00ED](0x00ED.md).
Migration 068 hides the 25 race item rows 20001 to 20903 (the client ships no `Parts/item_<name>` icon and no
title for them, the shop drew 25 blank tiles) and the slot exchange 1000 (no price option, no burst row), and
puts the repair scrolls 3000 and 3001 on the client text keys `ITEM_3000_TITLE` "50% Repair Kit" and
`ITEM_3001_TITLE` "100% Repair Kit". The client also knows 3002 3003 repair kits, 4001 to 4003 oils and 5000 third
slot, none has a burst row, none is ours. Needs the new image for the coin grant and 068 for the rows.

### The Item tab of the official server video, migration 071

The video (`www.youtube.com/watch?v=ViGZzEWl5sE`) shows exactly three tiles: "100% Repair Kit",
"Gold Coin" and "Slot Exchange". 071 makes 1000 visible on the client text keys `ITEM_1000_TITLE` and
`ITEM_1000_INFO` with the `slotchanger` icon (`Image/Parts/item_slotchanger_01` and `_02`), on three
use count options [0x00C6](0x00C6.md) 4201 4202 4203, and hides 2000 and 3000. 3001 keeps icon
`repair_full`, use type 5 and its row 4102 of unit type 3 amount 500, the full bar of 0x42AD20, so the
repair of [0x00B9](0x00B9.md) fills the kart. The "30%" GOLD label of the video tile is art, not a
field: the shop tile is `Image/Parts/item_repair_full_01` and `_02`, both painted "30% GOLD", while
`Image/Icon/item_repair_full` says "100% GOLD". `PartStatPackets::loadItemDefs` sends the rows by key
from the top so the tab reads 3001 2001 1000 like the video. A bought Slot Exchange row with uses shows
its icon in the char panel at 0x40 0xAD (`FUN_00429990` 0x429B78, the owned row of base key 1000 with
+0x10 above 0). Test `ItemTab071`. Needs the new image for the order and 071 for the rows.
