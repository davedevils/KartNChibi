## C2S PendantEquipReq and 0x0123 S2C PendantEquipAck

```
C2S  +0x00 i32 pendant_key, or -1 to unequip   size 4
S2C  +0x00 u32 pendant_key                     size 4
```

C2S gates: the row resolves in the 0x0119 list AND is owned per 0x011A, and the re entry
lock is clear. Clicking the already equipped key sends -1.
The re entry lock is ONLY cleared by S2C 0x0123, without a reply the pendant UI stays dead.
An unknown key on the ack just draws nothing, no crash. Echo -1 to confirm an unequip.
