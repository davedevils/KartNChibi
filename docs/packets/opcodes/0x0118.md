## S2C RoomLockState

```
+0x00  u32  kind
+0x04  u32  room_id
+0x08  u32  has_password
size   12
```

All three reads happen BEFORE the branch so the stream stays aligned for any kind.
kind 0 writes 0xBCE224, the has_password field of the room I am in (the 0x0013 field after
game_mode), when the room id matches. That store has no reader in this build.
kind 1 calls sub_4076B0 which writes the lobby room list record+0x6C, the has_password field
that draws Lobby_Room_Lock.
Any other kind is a no op. Both writes are bounds safe.
