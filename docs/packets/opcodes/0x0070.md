# 0x0070

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | FriendRequestResolved | sub_47B300 | SocialPackets::friendRequestResolved | 8 | friends | PROVEN |
| C2S | FriendReqAccept | sub_4820F0 | SocialPackets::parseIdRequest | 4 | friends | PROVEN wire, INFERRED accept |

## S2C FriendRequestResolved (family 0x0070 0x0071)

```
+0x00  u32  unused        read into a local, never referenced, MUST still be present
+0x04  u32  requester_id
size   8
```

Both 0x70 and 0x71 run the IDENTICAL handler, the client cannot tell accept from reject.
It only removes the pending row. On accept the server must ALSO push 0x6F result 1 or a
fresh 0x76 to BOTH parties.

## C2S id request family (family 0x0070 0x0071 0x0074 0x007B 0x007E 0x007F 0x0080)

```
+0x00  u32  player_id
size   4
```

Identical shape for FriendReqAccept 0x70, FriendReqReject 0x71, FriendDelReq 0x74,
BlockDelReq 0x7B, SmallTalkAccept 0x7E, SmallTalkDecline 0x7F, SmallTalkClose 0x80.
Accept versus reject and accept versus decline are INFERRED from button geometry and from
which UI path opens the chat window.
