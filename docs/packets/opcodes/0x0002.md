## S2C MessageTextBox

```
+0x00  UTF16LE wstr  text        sub_44EB60, dest wchar_t[160], NO bound
 var   u32           box_type
size   2*(len+1)+4
```

Wide twin of 0x0001 for literal server text, NOT a locale key. Clamp to 159 wchars.
box_type 2 still disconnects.

## Our server

Our login server sends an EMPTY 0x0002 with box_type 1 right after the 0x0007, and the
client needs it. `HandshakeHandler::handleClientAuth` in
`server/login/src/handlers/HandshakeHandler.cpp` calls `sendSessionInfo`, which is the
0x0007, then `sendDisplayMessage(session, u"", 1)`, then the 0x000E channel list. The
comment on that call says 0x02 sets `dword_F727F4` to 1 for connection confirmed, which is
the flag the stage acks 0x000F to 0x0016 are gated on.

The frame is six bytes:

```
+0x00  u16  0x0000   the wide NUL, an empty string
+0x02  u32  1        box_type
size   6
```

`HandshakeHandler::sendDisplayMessage` always writes two zero bytes after the text, so a
non empty text goes out NUL terminated as usual. An empty one is only the terminator. No
box is drawn for an empty text, the packet is used as the confirm flag alone.
It goes out on BOTH login paths. `sendSessionInfo` sends the 0x0007 with the profile blob
or with an empty one when the account owns no character, and the 0x0002 plus the 0x000E
follow it either way. The login server has no creation branch any more, the dead
`AwaitingCharacterCreation` branch and its `handleCharacterCreate` were removed, creation
is the game server after the 0x00A7, see [0x0003](0x0003.md) and [0x0004](0x0004.md).
