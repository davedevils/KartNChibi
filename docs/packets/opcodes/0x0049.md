# 0x0049

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | ItemGrantBroadcast | sub_47AAD0 | ItemPackets::grantBroadcast | 12 | items | PROVEN |
| C2S | ItemGrantedReport | sub_481180 | *ItemPackets::parsePickup | 8 | items | PROVEN |

## S2C ItemGrantBroadcast

```
+0x00  u32  player_id
+0x04  i32  item_id
+0x08  i32  slot_index   UNCHECKED, CLAMP TO 0..2 SERVER SIDE
size   12
```

Writes `dword_1BC08F8[slot_index + 171160*carSlot]`. An out of range index writes anywhere
in the 30 x 684640 car table.

## C2S ItemGrantedReport

```
+0x00  i32  item_id      0..21
+0x04  i32  slot_index   held count BEFORE the pending item commits
size   8
```

The CLIENT rolls the loot locally from a baked table and then informs the server.
There is no server grant packet and no pickup request packet. Sent with C2S 0x58 state 7.

## Our server

`RaceHandler::handleItemGrantReport` in `server/game/src/handlers/RaceHandler.cpp`, routed
from case 0x49 in `server/game/src/GameServerDispatch.cpp`, takes the report and relays it:

1. drop unless the room is Racing
2. drop a `item_id` outside 0..21, `ItemPackets::itemKindValid`, the table is
   0 booster, 1 big booster, 2 spike, 3 storm, 4 thunder, 5 handle, 6 turtle, 7 rabbit,
   8 shield, 9 smoke, 10 rocket, 11 hive, 12 angel, 13 bluerabbit, 14 ice, 15 flash,
   16 magnet, 17 hammer, 18 bomb, 19 dung, 20 devil, 21 devilred
3. clamp `slot_index` to 0..2, `ItemPackets::kSlotCount` is 3
4. feed `ItemPackets::ItemModel::applyGrant`, and keep our clamped index only when the model
   accepted it, the client owns the roll so a refusal only means our view drifted
5. `broadcastExcept` the sender, it already drew its own icon from the local roll

THE ROLL IS NOT OURS for a human. There is no server grant packet and no weight table read
out of the binary. `RaceHandler::sendGrid` does send one S2C 0x131 per human racer with 100
uniform random dwords, `RacePackets::itemRollStream`, as a plausible fill, but the client
still rolls what it wants and reports it here.

THE ROLL IS OURS for a CPU car. `RaceHandler::tickBots` in the same file picks from a fixed
seven entry table when a bot reaches an item box, so the weights are 1 in 7 each except
spike which sits in the table twice:

```
0  booster       1/7      2  spike     2/7
10 rocket        1/7     18  bomb      1/7
14 ice           1/7      1  big booster 1/7
```

The bot then sends the same S2C 0x49 grant broadcast with slot 0, waits a random 1500 to
4500 ms, and uses it. Box reach is 6.0 world units and the per bot box cooldown is 4000 ms.

`server/game/src/handlers/ItemHandler.cpp` used to hold a second implementation of this
handler that nothing routed to. It is gone, the file keeps only the two wired handlers,
`handleAbilityClass` for 0xF2 and `handleAbilityFire` for 0xCD.
