Exactly five literal pairs: button 0 {0,0}, 1 {1,0}, 2 {2,0}, 3 {3,0}, 4 {0,3}.
All five raise MSG_WAIT so all five need an answer. There is NO S2C case 44.

## Our server

`GameServer::handleStateChange` in `server/game/src/GameServerRaceHandlers.cpp` reads kind
and sub and calls `GameServer::quickMatch(session, kind)`. Kind outside 0..3 answers
`MSG_NO_MATCH_ROOM`. Otherwise the first waiting public room of that mode with a seat is
taken, else a fresh room is opened with `RoomSettings::fillWithBots` set, and the player
gets the same [0x0013](0x0013.md) chain a 0x2F join gets, plus the peer fan out.
`Room::fillWithBotsIfEnabled` then seats CPU cars up to the seat cap right after the
creator joins, `fillWithBots` used to be written and never read so a fresh room only ever
got one bot no matter the mode's real seat count. If that call seats nothing the old one
bot fallback still runs so the client never sees a room of one. The lobby 0x64 of our own
client lands in the same function, see [0x0064](0x0064.md).
