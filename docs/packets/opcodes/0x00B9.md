## S2C EquipUseAck

```
+0x00  u32  category
 cat 0: +0x04 blob[0x2C] character record, only rec+0x00 is consumed
 cat 1: +0x04 blob[0x38] kart record, only rec+0x00 is consumed
 cat 2: +0x04 blob[0x1C] item record,
        THEN +0x20 blob[0x10] kart_period_block ONLY when the 0xC1 catalog entry+0x0C of
        rec+0x04 is 4, 5, 6 or 7 AND the selected kart row exists
 cat 3: +0x04 blob[0x1C] part record
 cat 4: +0x04 u32 pet_sub_op,
        then blob[0x1C] previous_pet ONLY when sub_op == 2,
        then always one more blob[0x1C] new_pet
size   48 cat0, 60 cat1, 32 or 48 cat2, 32 cat3, 36 or 64 cat4, 4 for category above 4
```

CAT 2 AND CAT 4 ARE VARIABLE LENGTH AND THE LENGTH DEPENDS ON CLIENT SIDE CATALOG STATE.
If the item key is not in the 0xC1 catalog, or the selected kart is missing, the extra
16 byte read is SKIPPED and a server that sent it desyncs the rest of the frame.
CRASH: cat 4 writes `*(lookup(uid)+8)` with no null check.
Cat 3 slot map from catalog entry+0x38: 2..6 write character rec+0x08..+0x18 when
catalog+0x3C is -1 or matches the character base key, 0 writes kart rec+0x08,
1 writes kart rec+0x0C, 8 writes kart rec+0x10.

## C2S EquipUse

```
+0x00  u32  category
+0x04  u32  base_key   the def key of the owned row, FUN_00412AB0 returns rec+0x04
+0x08  i32  target_or_minus_one   only the custom car case passes a real value
size   12
```

Tab to category map: Char tab sub 0 -> 0, Char tab sub 5 Pet -> 4, Char tab sub 1..4 -> 3,
Car tab sub 0 -> 1, Car tab sub 1..3 -> 3, Item tab sub 0 -> 2.

## Our server

`InventoryHandler::handleInstall` in `server/game/src/handlers/InventoryHandler.cpp`,
through `CMD::C_GARAGE_INSTALL` in `GameServerDispatch.cpp`, one ack per request.

Two 0xB9 in one TCP write got one ack. `Session::parseLegacyPacket` in
`shared/src/src/net/Session.cpp` dispatches every complete frame of a read, that was never
the loss, `tests/server/test_session_frames.cpp` proves it on a loopback socket. The second
frame died in the per opcode flood floor of `RateLimiter`, 50 ms between two frames of one
opcode, checked in `GameServer::handlePacket` before the switch. `makeRateLimiterConfig`
in `server/game/src/GameServerBootstrap.cpp` now sets that floor to 0 for 0xB9 and 0xBA,
the global cap of 400 frames a second still holds.

Glass and back parts, 2026-09-24. The user's Dark Shades 2101 and Devil's Wings 2201 answered
the raw text MSG_UNKNOWN_ERROR, and the stock client in the docker got the same box for 2100 and
2200 with the same C2S bytes `03 00 00 00 34 08 00 00 FF FF FF FF`. `skinTargetFor` mapped a driver
skin through its own copy of the tab rule that knew body face and head only, so 71 of the 459
`def_kart_skin` rows (34 glasses, 36 back items, `monster_char_bady_015`) had no column and the
handler logged `part key N has no skin slot`. The 0xC2 burst already sent slot 5 and 6 for them.
Both now read `partSlotFor` of `server/game/include/util/GarageSlotRules.h`, the same map for
0xB9, 0xBA and 0xB8: body and bady 2, face 3, head and cap 4, glass 5, back and bag 6, anything
else 7 which no tab lists. `tests/server/test_kart_garage_rules.cpp` GarageCharSlots holds it.
Every refusal of this handler now goes out as the `0x0001` key box so the client shows
"Unknown Error !" from the text table, see [0x0001](0x0001.md), with box type 1, the OK box the
shop refusals use. The old type 0 drew a box with no button, the `dock1` capture shows it.
