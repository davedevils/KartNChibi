# 0x008A

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | MissionUnlocked | sub_47B990 | *MissionPackets::missionUnlocked | 8 | mission | PROVEN |

## S2C MissionUnlocked

```
+0x00  u32  mission_id
+0x04  u32  cleared    send 0
size   8
```

Appends ONE progress row WITHOUT clearing and WITHOUT dedupe.
Also raises the lobby new mission blink flag at 0x01ADF280 with a 64 bit timestamp,
the lobby clears it after 30000 ms.

## Our server

Since 2026-09-23 (needs the new image) `MissionHandler::handleMissionComplete` sends one 0x008A per
row a first clear adds to the chain of [0x0088](0x0088.md): `MissionPackets::rowsOpenedByClear` walks
the rows after the one just cleared, a row cleared out of order earlier goes with `cleared` 1 and the
first row not cleared goes with 0 and ends the walk. The 0x0088 of the next menu open is a full replace
of the same chain, so the missing dedupe never doubles a row. The lobby blink of 0x01ADF280 then lights
the top bar Mission button for 30 s like a new mission. A replay and the last mission send none. Test
`MissionChain.AFirstClearOpensTheNextRows`.
