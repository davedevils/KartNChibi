## S2C PriceRow

Handler `price_row_recv_0xc6` 0x478CB0, store `price_table_store` 0x451DC0 into the container
0x01A4C3C8, cap 1536, stride 0x1C, count at container+0xA804. Lookup `price_table_lookup` 0x451E00 by
key at rec+0x00. Readers: `price_row_draw_detail` 0x45D4A0, `price_row_draw_line` 0x454910,
FUN_0045E2E0 (the option list of the detail panel), `catalogue_price_key_resolve` 0x4852E0, the shop
tile drawers.

```
+0x00  u32  price_key    LOOKUP KEY, the element[0] of any price option row
+0x04  u32  f1           no reader in this build, container 0x01A4C3C8 and the five readers above checked
+0x08  u32  f2           no reader in this build
+0x0C  u32  unit_type    0 permanent UNIT_PERMANENT, 1 days UNIT_DAYS, 2 uses UNIT_TIMES, 3 durability UNIT_DUR
+0x10  u32  unit_amount  the days or uses printed with the unit word, not printed for 0 and 3
+0x14  u32  price_base   printed when price_sale is 0 or below
+0x18  u32  price_sale   printed and charged when above 0, FUN_0045E2E0 0x45E33x swaps the currency icon on it, shop_tile_draw_karts 0x4197D3 picks the sale tile background when it is not 0
size   28 exactly, ONE row per packet, no count prefix
```

BLIND APPEND, no key compare, so a second send duplicates the whole table.
REQUIRED BY THE SHOP: the resolver returns -1 when the def, the price option row or this
row is missing, and the client then refuses to send the buy verb. shop_price already names
unit_type unit_amount price_base price_sale, the two unknowns stay unknown_04 and unknown_08.

## Our server

`ShopHandler::sendPriceTableOnce` ships every row of `shop_price` once per session, at
login and again on the first 0x0010 that beats it, claimed by a per session flag so the
blind append never doubles the table. The recording carries 23 rows, 1001 to 1007 permanent,
2001 to 2007 one day, 3001 to 3007 seven days, plus the two gacha rows 4001 and 4002. Ours
carry 34, the same three tiers up to the sixth step plus our own 4001 to 4006 use rows, the
5001 to 5005 three day tier and three big keys. Migration 061 adds the seventh step,
1007 permanent sale 3000, 2007 one day 1000, 3007 seven days 5000, the tier the recording
gives every car craft part, since without those rows `price_row_lookup` fails and
`shop_roomcraft_grid_draw` 0x41A160 and its siblings skip the tile.

### The 23 rows and the currency, 2026-09-23

A sale above 0 is an Astro price, a base price is gold: the detail panel draws the Astro icon beside a sale
(0x45E36B), see [0x00B7](0x00B7.md). The burst thus sells every permanent option 1001 to 1007 for 3000 Astro,
the Gacha Coin 4001 for 1000 Astro and the Gold Coin 4002 for 2500 gold, every rental in gold. Migration 068
writes the 23 burst rows key by key over ours, deletes our coin packs 4003 to 4006 and the three day tier 5001
to 5005, and keeps 4101 4102 and the five rows of the disabled karts, 30 rows. The whole table and the tier of
each category are in [../SHOP_CATALOGUE.md](../SHOP_CATALOGUE.md).
