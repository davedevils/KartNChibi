# 0x0041

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | no case, C2S only | none | NONE | n/a | race progress | NO CASE |
| C2S | CheckpointReport | sub_4810D0 | *SpawnPackets::parseCheckpoint | 8 | race progress | PROVEN |

## C2S CheckpointReport

```
+0x00  u32  prev_checkpoint   value BEFORE the increment
+0x04  u32  new_checkpoint    after increment and wrap
size   8
```

C2S ONLY, there is NO dispatcher case 65. Sequence per lap on N checkpoints is
{0,1},{1,2},...,{N-1,0}. The first {0,1} at race start is NOT a completed lap.
Client accept window is detected >= expected and <= expected+5, tolerate bursts.

## Crossing rule

The report fires off the track COL face names, not off a trigger volume list.
`SpawnPackets::loadColCheckpoints` in `server/game/src/packets/gen/SpawnPackets.cpp` reads
`track.COL` and names the faces this way:

- header dwords are point count, face count, edge count, vertex count, then that many
  12 byte points, 56 byte faces, 20 byte edges and 12 byte vertices
- a face name is 34 bytes at face+22, upper cased before the compare
- a name containing `START` is checkpoint 0 and sets `hasStartFace`
- a name matching `CHECK_%03d` is that number, `CHECK_001` is checkpoint 1
- the count of distinct `CHECK_` numbers plus one must equal the head point count, a
  mismatch is only a warning, and a COL with no `START` face never closes lap zero

The client fires 0x41 when one of those faces sits under a wheel. `RaceSim::localCheckpointFace`
in `client/race/RaceSim.cpp` walks the four wheel probe points, asks the ground query for
the surface name, returns 0 for `START` and the parsed number for `CHECK_NNN`.
`RaceScreen::watchCheckpoints` in `client/screens/RaceScreen.cpp` keeps the last face seen,
ignores a repeat, and sends only when the new face equals `(current + 1) % count`. Face 0
also closes a lap. So a COL with no `START` face and a skipped number both stop the chain.

## Our server

`RaceHandler::handleCheckpoint` in `server/game/src/handlers/RaceHandler.cpp`, routed from
case 0x41 in `server/game/src/GameServerDispatch.cpp`, drops the report unless the room is
Racing and the track COL gave a checkpoint count, then feeds it to the per racer
`LapTracker`. Only a `LapComplete` result does anything, it bumps the lap, unicasts the
S2C 0x44 lap board advance, recalculates positions, broadcasts the S2C 0x45 standings, and
calls `completeFinish` on the last lap. A track with no readable COL logs once and ignores
every report.

The same COL read gives the drift boost observer of 0x40 its pad cells, `loadTrackCheckpoints`
keeps every `BOOST_NNN` face with its three signed half planes in `ColCheckpoints::pads`, then
reads the overlay pieces `track1.COL` to `track8.COL` for theirs without the name audit and
gives each cell the kind of line NNN of `boost.ini`. The checkpoint count still comes from the
base COL alone, see `docs/packets/opcodes/0x0040.md`.
