# 0x0011

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | MenuStageAck | sub_4793C0 | PacketBuilder::showMenu | 0 | menu | PROVEN |

## S2C stage acks

Shared payload, the block is in [0x000F](0x000F.md).

## Our server

WE NEVER SEND 0x0011 BEFORE 0x0012. The login burst ends on the lobby ack directly.
`GameServer::sendPlayerData` in `server/game/src/GameServerLoginBurst.cpp` closes the burst
with either S2C 0x0012 when the tutorial is done, or S2C 0x0016 when it is not. That second
one is `CMD::S_UI_STATE_14`, whose NAME is the stage 14 licence screen and whose VALUE is
0x16, do not read the 14 as an opcode. The comment there records the proof, 0x11 lands on
stage 5 the menu so the IDA stage labels are off by one. Room list rows follow that ack, never precede it, because the ack runs
`sub_408020` and that wipes the grid.

Our two real 0x0011 senders are both later than login:

- `GameServer::handleChannelSelect` in `server/game/src/GameServerRoomHandlers.cpp` answers
  a channel select for any screen other than 0x0E with the bare 0x0011, screen 0x0E gets
  0x0012 plus the room list
- `LicenseHandler::handleLicenseResult` in `server/game/src/handlers/LicenseHandler.cpp`
  sends it after the pass or fail message box to put the player back in the menu

So a client that never reaches those two paths sees no 0x0011 in a whole session.
