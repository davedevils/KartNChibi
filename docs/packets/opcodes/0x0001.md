## S2C MessageKeyBox

```
+0x00  ASCII cstr  message_key   sub_44EB30, dest char[256], NO bound
 var   u32         box_type
size   strlen(message_key)+1+4
```

The login failure channel. No numeric login result code exists in the client.
The failure identity IS the ASCII key, resolved through def_trans_index.txt.
box_type 2 calls `sub_4775C0(net, 0)` = disconnect.
Four keys are strstr special cased and force disconnect whatever box_type says:
`MSG_SERVER_NOT_READY` (no disconnect, sets byte_B23180 = 0), `MSG_DB_ACCESS_FAIL`,
`MSG_REINPUT_IDPASS`, `MSG_INVALID_ID`. Keep the key short, dest is 256 bytes.

## Our server keys, 2026-09-24

The `0x0002` box shows its text as sent, so a key sent there drew raw, `MSG_UNKNOWN_ERROR` on
every refused equip for one. Keys the text table knows go out on `0x0001` through
`PacketBuilder::messageKey`: the equip, remove and delete refusals of `InventoryHandler`,
`MSG_DB_ACCESS_FAIL` of the ghost enter, `MSG_REINPUT_IDPASS` of the login reauth. The shop keeps
`ShopPackets::rejectAscii`. Keys the table does not know (`MSG_KICKED_CHEAT`, `MSG_PLAYER_NOT_FOUND`,
`MSG_MAP_LEVEL_HIGH` and the like) became plain English text on `0x0002`. The clone resolves a
`0x0001` key through `def_trans_index` too, before it drew the key raw, `msg_no_money` of the user.
