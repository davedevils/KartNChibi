## C2S OpenLobbyRequest or HostStartRace

```
payload none
```

GOTCHA, two meanings. From a menu it is open lobby. From the 3D room `sub_410550` resends
it EVERY FRAME with MSG_WAIT up once ALL of: I am room master, every other occupied slot has
ready_state non zero, occupied count is not exactly one, and 30000 ms elapsed.
Handle by room state, not by opcode.

## S2C stage acks

Shared payload, the block is in [0x000F](0x000F.md).

## Our server

Our dispatch reads the C2S 0x12 as `CMD::C_LOBBY_ENTER` only, it never reads it as a host
start. The arm in `GameServer::dispatchPacket` in `server/game/src/GameServerDispatch.cpp`
does three things in order:

1. `leaveCurrentRoom(session)`, which drops the sender from its room, broadcasts S2C 0x2E
   with the leaver character id, hands the host over with S2C 0x23 when the host left, and
   removes the room when the last human is gone.
2. `session->send(Packet(CMD::S_SHOW_LOBBY))`, the bare S2C 0x12 lobby ack.
3. `GameServer::sendLobbyRoomList(session)` in `server/game/src/GameServerRoomHandlers.cpp`,
   which drips one S2C 0x2E then one S2C 0x2D per live room. The ack runs `sub_408020` and
   that wipes the grid, so the rows MUST follow the ack, never precede it.

So a 0x12 sent from the 3D room is answered as an exit to the lobby on our side. The host
start path is C2S 0x40 with an empty body, `CMD::C_MOTION` in the same dispatch, where the
payload size tells a motion sample from a start request.
