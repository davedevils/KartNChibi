# 0x006A

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | MotionBlock | sub_47AFE0 | *ItemPackets::raceValue | 6 | motion | PROVEN |
| C2S | RaceValuePush | sub_481C20 | *ItemPackets::parseRaceValue | 2 | motion | PROVEN |

## S2C MotionBlock

```
+0x00  u32  player_id
+0x04  i16  delay_ms
size   6
```

MUST be documented because it silently makes S2C 0x40 a no op. While car+686272 is non zero
the 0x40 handler consumes the entry bytes and THROWS THE SAMPLE AWAY.
After delay it runs a client side synthetic glide of 8 fabricated samples, then clears
700 ms later. The i16 is read inside the id guard.
LIVE SERVER BUG: `PacketBuilder::shopUpdate` builds 0x6A as {i32 gold, i16 cash}, the exact
MOTION_BLOCK shape, and InventoryHandler sends it after a sell.

## C2S RaceValuePush

```
+0x00  i16  value
size   2
```

Two bytes, no id. Server prepends the sender id and rebroadcasts the 6 byte S2C 0x6A.
