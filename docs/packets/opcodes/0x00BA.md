# 0x00BA

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | UnequipAck | sub_484B10 | *InventoryPackets::unequipPetAck | 4 or 32 | garage | PROVEN |
| C2S | Unequip | sub_4843D0 | *InventoryPackets::parseRemove | 8 | garage | PROVEN |

## S2C UnequipAck

```
+0x00  u32  category
+0x04  blob[0x1C] record, PRESENT ONLY for categories 2, 3 and 4
size   4 for categories 0, 1, 5, 6 and anything else, 32 for 2, 3 and 4
```

DESYNC TRAP: appending a record for category 0 or 1 leaves the bytes in the frame.
The handler restores DEFAULTS out of the def catalogs, the record only identifies the row.
CRASH: cat 4 writes `*(lookup(uid)+8)` with no null check.

## C2S Unequip

```
+0x00  u32  category
+0x04  u32  instance_id
size   8
```

The Remove of the garage (`sub_413D30` button 3, `sub_412D30`) sends this with the BASE key of the
owned row, not an instance id. `sub_415AA0` only lets it go when the worn key differs from the
default: on the Car tab the paint (0xC2 +0x38 = 0) compares the kart record +0x08 with the kart def
+0x84, the plate (1) +0x0C with +0x88, the antenna (8) +0x10 with +0x8C. The stock answer for
category 3 is the part record, `sub_484B10` then copies the kart def key back into the kart record,
so removing a paint puts the kart on its default paint, RED 9007 on every kart row of our burst,
the plate goes back to 9100 and the antenna to 0. The paint slot does allow Remove.

## Our server

`InventoryHandler::handleRemove`. Category 3 answers the part record then 0x00BC with the
selected character and kart. Until 2026-09-23 it wrote 0 into `owned_kart.skin_primary`, the wire
patched the zero to 9007 in `InventoryPackets::kartBlob` but every other reader of the row met a
zero paint key, and the stock kart builder returns null on a zero paint or plate. Now
`resetWornPart` writes `kartSkinDefaultKey` (`server/game/include/util/GarageSlotRules.h`), the
same key the client puts back, and migration 070 heals the zeros already stored. A character slot
still goes to 0, `selectedCharacterRow` heals body face and head on the next read.

The black paint error the user met on 2026-09-23 was not this opcode: that paint had expired
(day 45886, the client counted 45890), so the garage showed Delete and Buy at the Remove spot and
the click sent 0x00B8, see there.
