## C2S TrackSelectRequest and 0x0035 S2C TrackSelectBroadcast

```
+0x00  u32  track_id
+0x04  u32  weather
size   8 both directions
```

C2S: client refuses to send when its license grade is below the track catalog +72 grade.
S2C: calls `sub_4538B0` FIRST so it clears the MSG_WAIT the C2S raised.
An id missing from the 0xC3 track catalog dereferences NULL at `v17 = *(v14+68)`.
weather 0 1 2 pick a room overlay, other values fall to default.

## Our server

S2C: the last frame of the room chain, `GameServer::sendRoomScreen` in
`server/game/src/GameServerRaceHandlers.cpp` closes the [0x0013](0x0013.md) burst with
`PacketBuilder::roomTrackSelect(defaultRoomTrack(mapId).trackId, 0)`, for the 0x2D create,
the 0x2F join, the 0x2C and 0x64 quick match and the room screen resend after the results.
The 0x2F join path used to send no 0x35, so a joiner had no track on its panel. The id is a
`track_catalog.track_id` that the 0xC3 catalogue resolves, the map id never goes on the wire.

C2S: the `S_ROOM_TRACK_SELECT` arm in `server/game/src/GameServerDispatch.cpp` looks the
track up in `track_catalog`, stores its map id on the room and broadcasts the same 8 bytes
back, an unknown id answers the current track to the sender alone.
