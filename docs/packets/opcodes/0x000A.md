## S2C ProfileRefresh

```
+0x00  u8   channel_level_band
+0x01  u8   level
+0x02  u32  exp_current
+0x06  u32  astro
+0x0A  u32  gold
+0x0E  u32  selected_character_instance_id
+0x12  u32  selected_kart_instance_id
+0x16  u8   unknown
+0x17  u8   session_role_privilege
+0x18  u8   unknown
+0x19  u8   unknown
+0x1A  u32  exp_floor_current_level
+0x1E  u32  exp_required_next_level
+0x22  u32  equipped_title_key
size   38 exactly, PACKED, no padding
```

14 sequential reads into the same destinations as the 0x0007 blob span, but it SKIPS the
2 padding bytes. That is why 38 here and 40 inside 0x0007. Touches no UI, closes no modal.

## Our server

The last u32 at plus 0x22 lands on the worn pendant 0x01A20B2C (`0x47D48A`), not on rank
points. Since 2026-09-23 (needs the new image) `connectionOkWithPlayer` writes
`characters.pendant_key` there. Test `PendantWire`.

Since migration 071 the floor at +0x1A and the next at +0x1E come from the curve of
[../LEVEL_CURVE.md](../LEVEL_CURVE.md), the `y` the char info prints in `EXP : x / y`.
