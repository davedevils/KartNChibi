# 0x0068

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | HardTeleport | sub_47AE30 | MotionPackets::teleport | 20 | motion | PROVEN |
| C2S | RespawnResult | sub_481A80 | *SpawnPackets::parseRespawn | 16 | motion | PROVEN |

## S2C HardTeleport

```
+0x00  u32  player_id
+0x04  f32  pos_x
+0x08  f32  pos_y
+0x0C  f32  pos_z    UP AXIS
+0x10  f32  yaw_degrees   normalized to [0,360)
size   20
```

DANGER: only player_id is read BEFORE the lookup, the other 16 bytes are read INSIDE the
guard, so an unspawned id drops the whole teleport and desyncs.
No interpolation. It does NOT move the owning client physics body, relay it to everyone
EXCEPT the sender. Same coordinate space and units as the decoded 0x40 position.

## C2S RespawnResult

```
+0x00  f32  x
+0x04  f32  y
+0x08  f32  z
+0x0C  f32  yaw_degrees
size   16
```

The CLIENT decides its own respawn and only informs the server. Two producers:
rescue picks the nearest follow path node with z+3.0, or a WARP_%03d face reads warp.ini.
Rebroadcast as S2C 0x68 with the id prefixed, to everyone but the sender.
