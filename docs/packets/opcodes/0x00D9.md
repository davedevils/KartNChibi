# 0x00D9

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | PlayerAppearanceUpdate | sub_47D540 | NONE | 164 | room and grid | PROVEN |
| C2S | SelectCharacterAndKart | sub_4712A0 | NONE, MIRROR_UI echo | 68 | garage | PROVEN |

## S2C PlayerAppearanceUpdate

```
+0x00  u32         player_id
+0x04  blob[0x2C]  character block, same as 0x0021 and 0x003E
+0x30  blob[0x38]  owned kart block
+0x68  blob[0x3C]  custom car block
size   164 exactly
```

All 164 bytes are consumed before the slot lookup, unknown id is stream safe.
Returns early when the room stage is not initialised or no occupied slot matches.
SELF CASE: when the id is mine the client also writes the two selection globals.

## C2S SelectCharacterAndKart

```
+0x00  u32         character_instance_id
+0x04  u32         kart_instance_id
+0x08  blob[0x3C]  custom car block
size   68 exactly
```

Custom car block: `u32 custom_car_id` then 7 x { u32 part_base_key, u32 part_field }.
A missing part writes 0 into the base key and leaves the second dword zero.
Only sent when the selection actually changed. The block is 60 zero bytes unless the
custom car flag is on.
Answer by broadcasting S2C 0x00D9 INCLUDING the sender, the self case is what updates the
selection globals.
