## S2C ClientFileCheck

```
+0x00  i32  count
 then  count x { char[12] relative_path FIXED ASCII slot, u32 expected_checksum }
size   4+16*count
```

After the loop it spawns a worker thread that runs FOREVER until a flag is cleared.
Two checks per pass. First it counts how many `./pakNNN.dat` for 000..031 actually exist and
compares that number to COUNT, a mismatch shows MSG_FILECHECKERROR and disconnects.
Second, for each record it hashes `./` plus the name and compares, same fatal path.
So count is doing DOUBLE DUTY as the expected pak file count.
