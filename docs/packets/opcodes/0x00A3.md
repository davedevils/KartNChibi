## S2C LicenseTestResult

```
+0x00  u32  has_currency
+0x04  u32  has_item
+0x08  blob[0x0C]  license progress entry { key, passed, unknown }
 -- only when has_currency == 1 --
+0x14  { u32 key, u32 count }
 -- only when has_item == 1 --
 var   u32 reward_item_type then the reward blob
size   20 base, +8 with currency, +4+blob with item
```

Blob size by the WIRE type, unlike 0x8C which uses the client side definition:
0 0x2C, 1 0x38, 2 0x1C, 3 0x1C, 4 0x1C, 5 0x30, 6 0x84+u8[+0x34], 7 0x08.
CLIENT SIDE CURRENCY PREDICTION: while in stage 13 the handler scans the 0xC5 definition
container for the matching key and does `exp += def+0x30` and `gold += def+0x34`.
Push the authoritative numbers with S2C 0x0A right after or the HUD drifts by exactly the
definition values.

## C2S LicenseTestSubmit

```
+0x00  u32  license_key
+0x04  u32  echo of test_def+0x2C
+0x08  u32  echo of test_def+0x34
size   12
```

Only sent when that key is not already passed. Fields 2 and 3 are echoed straight out of
the client own 0xC5 table, DO NOT TRUST THEM, recompute server side.
