## A hole in the numbering, settled 2026-09-23

Nothing in this build reads or sends 0x0106. It is a hole in the numbering, like 0x0127 to 0x012D and 0x0134.

S2C, no case. The dispatcher `sub_4777C0` does `MOVZX EAX,AX; DEC EAX; CMP EAX,0x134; JA 0x4782D2`, then
`MOVZX EAX,byte [EAX+0x478638]` and `JMP [EAX*4+0x4782D8]`. The index byte of 0x0106 sits at 0x47873D and
holds 0xD7 (215). Jump table entry 215 at 0x478634 is 0x4782D2, `POP EDI; POP ESI; RET 4`, the same no op target
as an opcode past 0x135. The neighbours are real cases: 0x0104 is case 181 (0x47E3A0 OwnedPetList), 0x0107 is case
182 (0x47E400 CarCraftPresetList). A frame with this number is consumed and dropped, nothing reads its payload.

C2S, no sender. Every packet the client builds starts with BeginPacket 0x44ECD0 (107 call sites) and one of those
sites is the empty body sender 0x4803A0, which takes the opcode from its 17 callers, each a `PUSH imm` then the
call. Every site resolves to its opcode and none is 0x0106. The value 0x106 shows up only away from any packet code: `PUSH 0x106` at 0x4109B7 is a coordinate of the image draw call 0x4412A0, and the rest are arithmetic in the CRT (0x528CA4 to 0x529399), the scenario HUD (0x4B5CB2) and two stack locals of `car_apply_kart_loadout` and 0x4D11D0.

Not in the captured login burst `server/data/reference_login_burst.bin` either (733 frames).

## Our server

No symbol in `shared/src/include/net/Protocol.h`, never sent. An inbound frame with this number falls to the
default of `GameServer::handlePacket` in `server/game/src/GameServerDispatch.cpp`, which logs it as
`NOT HANDLED ... reason=no16bitRoute` and answers nothing, which is right since no client path waits for it.
