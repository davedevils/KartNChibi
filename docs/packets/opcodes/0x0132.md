# 0x0132

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | UserListPage | sub_47EE30 | SocialPackets::userListPage | 296 | user list | PROVEN |
| C2S | UserListPageReq | sub_483CC0 | SocialPackets::parseUserListPageReq | 4 | user list | PROVEN |

## C2S UserListPageReq

```
+0x00  u32  page_index   zero based
size   4
```

Arrives unprompted every 10000 ms while the user list tab is open, plus on every arrow.

## S2C UserListPage

```
+0x000  u32  current_page
+0x004  u32  page_count
+0x008  u32  vptr_slot            overwrites the container C++ vptr, 0 is proven safe,
                                   safest value is the constructor 0x005A3D3C
+0x00C  UserListEntry[7]  FIXED 7 slots of 0x28, always send all 7
+0x124  u32  entry_count          0..7, a larger count walks past the array
size   296 EXACTLY, regardless of how many users are on the page
```

UserListEntry:

```
+0x00  u32       player_id
+0x04  wchar[14] name           FIXED 28 byte slot NUL terminated, NOT a wire string
+0x20  u32       level
+0x24  i32       pendant_slot   <= 0 default sprite, 1..63 the pendant icon bank,
                                 above 63 walks past the sprite array
```

Zero fill the unused slots. player_id is echoed verbatim as C2S 0x0133.

## Our server

`SocialHandler` user list page. Since 2026-09-23 (needs the new image) the pendant slot is the
worn `characters.pendant_key`: `sub_429D30` draws `UserList/pendant_%02d_00` by that number,
the old `pendant_slot` column was never written so every row showed the default sprite. Our
client draws the rows of the asked page from its first slot, it drew nothing past page one.
