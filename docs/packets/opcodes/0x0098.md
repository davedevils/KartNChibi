# 0x0098

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | GiftSendOk | sub_47BEF0 | ShopPackets::giftOk | 220 | gift | PROVEN |
| C2S | GiftBuy | sub_482880 | ShopPackets::parseGift | 12+2 strings | gift | PROVEN |

## S2C GiftSendOk

```
+0x00  u32         astro   -> profile blob +0x4A8
+0x04  u32         gold    -> profile blob +0x4AC
+0x08  blob[0xD4]  read and DISCARDED but MANDATORY
size   220 exactly
```

MONEY ORDER TRAP: 0x98 is (astro, gold), REVERSED versus 0x00B7 and 0x0112 which are
(gold, astro).

## C2S GiftBuy

```
+0x00  u32           category    0..6
+0x04  UTF16LE wstr  recipient_name
 var   u32           base_key
 var   i32           price_key   -1 when the client could not resolve it
 var   UTF16LE wstr  gift_message
size   12+2 strings
```

Raises MSG_WAIT when price_key >= 0 else MSG_UNKNOWN_ERROR, then sleeps 100 ms.
NEVER echo 0x98 back verbatim, the S2C form needs 220 bytes.
