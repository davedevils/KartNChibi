## S2C RaceGo

```
+0x00  u32  start_delay_param
size   4
```

THE RACE GO. `sub_402400` returns immediately unless `flt_1B19740 >= 0.0`, i.e. the LOCAL
player 0x3E has been processed. Send 0x3A before the local 0x3E and the race never starts.
stage+92336 = max(0, 200 - delay). Send once, after 0x14, all 0x3E and 0x0D.

## Countdown after the GO

The GO is not the green light. The client runs its own countdown after 0x3A and a real kart
only moves about 10 s later, measured between 9.5 s and 11.5 s on our races. The server
never sends a tick for it, S2C 0x3B exists but has no client handler.

Our server holds the CPU cars for exactly that window.
`server/game/src/handlers/RaceHandler.cpp` declares `BOT_GO_HOLD_MS = 10000` with the note
that the client runs its own countdown, and `RaceHandler::tickBots` skips every bot while
`now < live.raceStartMs + BOT_GO_HOLD_MS`, so the grid stays parked until the lights go
green on the human screens. `live.raceStartMs` is set in `RaceHandler::armBots`, which runs
from `goRace` right after `startRace` broadcast the 0x3A.

The server race clock starts at the same moment, `m_raceStartTimes` is written in
`RaceHandler::startRace` just before the 0x3A goes out, so every finish time we record
carries this 10 s hold inside it. Anything else timed off the GO must add the hold too, or
it fires while every car is still on the line.
