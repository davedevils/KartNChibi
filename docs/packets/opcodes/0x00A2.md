## S2C LicenseProgressList

```
+0x00  i32  count
 then  count x { u32 license_key, u32 passed, u32 unused_08 }
size   4+12*count
```

Container conn+0x848340, records at +0x04 stride 12, count at +0x304, sub_450920 appends.
unused_08 has no reader in this build: the row readers go through sub_4509B0 (sub_437770,
sub_437820, sub_41D2D0 and the other license test stages, sub_47C3C0) and read +0x00 and +0x04 only.
THE HANDLER DOES NOT CLEAR and there is no dedupe, send this exactly ONCE per session.
0xBE does not clear it either.
OFF BY ONE: the insert guard is `if (count > 64) return -1` so index 64 is allowed and its
12 bytes land on the count field. Send AT MOST 64 rows.
Key convention proven from the UI: `license_key = test_index + 10*grade`, test_index 0..3,
grade 0..2, so 0,1,2,3,10,11,12,13,20,21,22,23.
