## S2C PendantDefinition

```
+0x00  u32         visible_flag    -> rec+0x00, sub_451340 and sub_451370 skip rows where it is 0, sub_46EBC0 draws only nonzero
+0x04  u32         pendant_key     -> rec+0x04  PRIMARY KEY, sub_451290 matches the owned list on it
+0x08  ASCII cstr  icon_base_name  -> rec+0x08, dest 33
 var   ASCII cstr  name_loc_key    -> rec+0x29, dest 33, drawn by sub_46EF50
 var   ASCII cstr  desc_loc_key    -> rec+0x4A, dest 34, drawn by sub_46EF50
size   8+3 cstr lengths, record is 0x6C
```

Container 0x01A9373C, cap 64, stride 0x6C, sub_451300 appends. Every dword of the record has
a reader, there is no unknown field in this packet.
icon_base_name feeds `Icon/%s_%02d.png` and `Icon/%s_s.png`, shipped set is
`pendant_NN_00.png`, `_01.png`, `_s.png`.
SERVER BUG: `PacketBuilder::entityStrings` writes the three strings as UTF16 while the
client reads ASCII, that would desync the frame. The symbol has no callers.

## Our server

The login burst sends every `pendant_def` row, since 2026-09-23 ordered `visible DESC` so the
hidden key 13 comes last: `sub_46EDB0` counts hidden rows in its hit test and a hidden row in
the middle would shift every cell after it. Our client stores the rows on `Session` and the
pendant box draws them.
