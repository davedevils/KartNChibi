# 0x006F

| Direction | Name | Client fn | Server symbol | Size | System | Status |
|---|---|---|---|---|---|---|
| S2C | FriendAddResult | sub_47B3C0 | SocialPackets::friendAddResult | 4, 48 or 40 | friends | PROVEN |
| C2S | FriendAddByName | sub_481F00 | SocialPackets::parseNameRequest | 2*(n+1) | friends | PROVEN |

## S2C FriendAddResult

```
+0x00  u32  result
 -- result == 1 --
+0x04  blob[0x2C]  FriendRecord   appended to the 100 slot friend list
 -- result == 12 --
+0x04  blob[0x24]  RequestRecord  appended to the 100 slot pending list
 -- any other result --
 nothing after the u32
size   4, or 48, or 40
```

FriendRecord and RequestRecord layouts are under 0x0076 and 0x0078.
Result codes drive the shared message table: 0 MSG_FRIEND_ADD, 1 MSG_FRIEND_ADD_OK,
2 MSG_FRIEND_DUP, 3 MSG_FRIEND_MAX, 4 MSG_FRIEND_ACCEPTER_MAX, 5 MSG_FRIEND_NOUSER,
6 MSG_FRIEND_DEL, 7 MSG_NOTE_INPUTUSER, 8 MSG_NOTE_INPUTNOTE, 9 MSG_NOTE_NOUSER,
10 MSG_NOTE_SEND, 11 MSG_NOTE_NOSEND. Code 12 shows no dialog.
When the messenger is closed the records still parse but no dialog shows.

## C2S name request family (family 0x006F 0x007A 0x007D 0x006C 0x0072)

```
+0x00  UTF16LE wstr  target_name
size   2*(len+1)
```

Identical shape for FriendAddByName 0x6F, BlockAddByName 0x7A, SmallTalkReq 0x7D,
RoomInviteByName 0x6C and UserInfoReqByName 0x72. The server must resolve the name.
